\chapter{Renderer: Architecture and Implementation}
\label{ch:architecture}

This chapter describes the renderer itself: a from-scratch CUDA/OptiX volumetric path tracer for the
Gaussian kernel-mixture volumes of \Cref{sec:kernel-mixture}. Its design answers one question
differently from the reference: \emph{given a camera ray, how is the next scattering event found?}
The reference~\cite{DSYG} marches the ray segment by segment through the sorted sequence of primitive
boundaries and root-finds the scatter distance; this renderer instead collects all of a ray's
primitives in a \emph{single} acceleration-structure traversal and samples the scatter distance in
\emph{closed form}, with no sorting, no marching, and no root-finding. The two halves of that
design---single-trace collection (\Cref{sec:collection}) and analog-decomposition scatter sampling
(\Cref{sec:adt})---are the thesis's primary contribution; the supporting machinery (direct lighting,
data structures, and the OptiX configuration) is described in
\Crefrange{sec:direct-lighting}{sec:gpu-impl}.

\section{Pipeline overview}
\label{sec:pipeline}

The renderer ingests a set of Gaussian primitives (a PLY file of centres, covariances encoded as
scale + rotation quaternion, densities, and albedos), builds a two-level OptiX acceleration structure
over them (\Cref{sec:gpu-impl}), and path-traces the image in a single megakernel launched per pixel.
Each path repeats four steps per bounce: \emph{collect} the primitives the current ray segment
intersects (one trace), \emph{sample} a scattering distance from them (the argmin of per-primitive
free flights), \emph{shade} the event by next-event estimation against the environment, and
\emph{continue} along a phase-sampled direction until Russian roulette terminates the path. Per-pixel
radiance is accumulated across samples by a single-pass online mean (\Cref{sec:direct-lighting}). The
entire bounce loop lives inside the ray-generation program; \Cref{sec:gpu-impl} explains why this
megakernel structure---rather than a wavefront of separate kernels---is the right fit for this
workload. \Cref{fig:pipeline} contrasts the per-bounce work of the reference with this renderer's.

\section{Single-trace primitive collection}
\label{sec:collection}

To sample a scattering event along a ray, the renderer must know which primitives the ray passes
through and over what intervals. The reference constructs this information incrementally, advancing the
ray from one primitive boundary to the next and issuing a fresh acceleration-structure query at each
step; for a ray crossing $N$ overlapping primitives this is $O(N)$ traversals. The observation behind
this renderer's collection scheme is that, because every primitive is a bounded convex region (a
transformed unit sphere, \Cref{sec:gpu-impl}), \emph{all} of the ray's entry points can be gathered in
a \emph{single} traversal, and the corresponding exits then computed analytically.

Concretely, the scene is traced once per scattering event with an \emph{any-hit} program and no
closest-hit program (the ray flag \texttt{OPTIX\_\allowbreak RAY\_\allowbreak FLAG\_\allowbreak DISABLE\_\allowbreak CLOSESTHIT}). Because any-hit
fires for every intersection without terminating the ray, a single trace visits every primitive the
ray meets. Back-face culling (\texttt{OPTIX\_\allowbreak RAY\_\allowbreak FLAG\_\allowbreak CULL\_\allowbreak BACK\_\allowbreak FACING\_\allowbreak TRIANGLES}) discards the
exit intersections, so the any-hit program records only \emph{entries}---each a pair of hit distance
$t_{\text{hit}}$ and primitive index, appended to a per-ray buffer. The matching exit of
any primitive is not traced at all: since the primitive's geometry is known, the exit distance follows
in closed form from the ray--sphere intersection. One traversal therefore replaces the reference's
$N$, and the buffer holds exactly the data the scatter sampler needs.

The entry buffer is a structure-of-arrays, \texttt{HitBufferSoA}, storing the hit distances and
primitive indices in separate arrays (\SI{4}{\byte} and \SI{2}{\byte} per entry respectively) so that
the sampler's sequential scan over hits is coalesced. It is a per-ray buffer held in fast local memory
with a fixed capacity (\Cref{sec:gpu-impl}); overflow is \emph{detected} rather than corrected---a
dropped hit biases the pixel toward under-absorption, but a device counter flags the event instead of
letting it pass silently. Two categories of primitive contribute to a scattering event: those the ray is
already \emph{inside} at the segment's start (the camera may begin inside the medium, and after a
scatter the new ray starts inside whatever primitives contain the scatter point), tracked in an
\emph{active set}; and those the ray \emph{enters} along the segment, delivered by the trace into the
hit buffer. The sampler in \Cref{sec:adt} draws candidates from both.

\section{Analytic optical depth}
\label{sec:analytic-od}

The property that makes both single-trace collection and closed-form scatter sampling possible is the
analytic optical depth of a single Gaussian (\Cref{sec:kernel-mixture}). Write primitive $k$'s extinction
as $\sigma_{t,k}(\bm{x}) = C_k\,\exp\!\big(-\tfrac12\lVert S_k^{-1}R_k^{\!\top}(\bm{x}-\bm{\mu}_k)\rVert^2\big)$,
with rotation $R_k$, per-axis scales in $S_k=\operatorname{diag}(s_{ki})$, and peak extinction
$C_k=\sigma_{t,k}\big((2\pi)^{3/2}\prod_i s_{ki}\big)^{-1}$. Substituting the ray $\bm{r}(s)=\bm{o}+s\bm{\omega}$
and \emph{whitening}---$\bm{y}(s)=S_k^{-1}R_k^{\!\top}(\bm{r}(s)-\bm{\mu}_k)=\bm{a}+s\bm{b}$ with
$\bm{a}=S_k^{-1}R_k^{\!\top}(\bm{o}-\bm{\mu}_k)$ and $\bm{b}=S_k^{-1}R_k^{\!\top}\bm{\omega}$---reduces the exponent
to a one-dimensional quadratic. Completing the square in $s$,
\[
  \tfrac12\lVert\bm{y}(s)\rVert^2 = \tfrac12 w^2 (s-s^\star)^2 + \tfrac12 d_\perp^2,\qquad
  w=\lVert\bm{b}\rVert,\quad s^\star=-\frac{\bm{a}\cdot\bm{b}}{w^2},\quad
  d_\perp^2=\lVert\bm{a}\rVert^2-\frac{(\bm{a}\cdot\bm{b})^2}{w^2},
\]
where $s^\star$ is the ray's closest approach to the whitened centre, $w$ its whitened speed, and
$d_\perp$ the whitened perpendicular distance. The remaining integral is Gaussian and evaluates to an
error function:
\[
  \tau_k(t_0, t_1) = \int_{t_0}^{t_1}\! \sigma_{t,k}\big(\bm{r}(s)\big)\,\mathrm{d}s
  = \underbrace{C_k\, e^{-\tfrac12 d_\perp^2}\,\sqrt{\tfrac{\pi}{2}}\,\tfrac1w}_{\displaystyle C_k'}
  \big[\operatorname{erf}(u_1) - \operatorname{erf}(u_0)\big],\qquad u_i=\tfrac{w}{\sqrt2}(t_i-s^\star).
\]
The prefactor $C_k'$ is a per-ray constant (the per-primitive part of which is precomputed), so each
$\tau_k$ costs one exponential and two error-function evaluations. Because $\operatorname{erf}$ is
strictly monotonic, $\tau_k$ is \emph{monotonic and invertible} in $t_1$: given a target optical depth
$\tau$, the distance at which primitive $k$ alone accumulates it follows from a single inverse error
function,
\[
  t(\tau) \;=\; s^\star + \tfrac{\sqrt2}{w}\,
  \operatorname{erf}^{-1}\!\Big(\operatorname{erf}(u_0) + \tau/C_k'\Big),
\]
the closed-form inverse the next section turns into a sampler.

\section{Sort-free scatter sampling}
\label{sec:adt}

A volumetric path tracer must sample the distance to the next collision in proportion to the collision
density $\sigma_t(\bm{r}(t))\,T(t)$, i.e.\ draw a free flight (\Cref{sec:volumetric-light-transport}).
For a single homogeneous medium this means solving $\tau(t) = -\ln(1-\xi)$ for an exponentially
distributed target; for the \emph{sum} of overlapping primitives the reference does it by marching and
root-finding. This renderer avoids both by appealing to the structure of decomposition
tracking~\cite{Kutz2017}.

\paragraph{The argmin rule.} Decomposition tracking rests on the fact that a free flight through a sum
of components is distributed as the \emph{minimum} of independent free flights through each component
taken separately. Each primitive here \emph{is} such a component, and---by \Cref{sec:analytic-od}---can
draw its own free flight in closed form: sample a per-primitive target
$\tau_k = -\ln(1-\xi_k)$ with $\xi_k\sim\mathcal{U}[0,1)$, then invert to the distance $t_k$ at which
primitive $k$ alone reaches $\tau_k$. The scattering event is the nearest of these,
\[
  t_{\text{scatter}} = \min_k t_k ,
\]
taken in a single linear pass over the ray's primitives (those in the active set, plus those in the
hit buffer). Where the reference marches the ray and, within each segment, root-finds the scatter
distance---selecting the next boundary by a running minimum at every step---this scheme needs neither
march nor root-find: the per-primitive inverse is exact (one $\operatorname{erf}^{-1}$), so a single
argmin over closed-form free flights gives the scatter point directly. The minimum reproduces
\emph{exactly} the distribution the reference's marching produces (it is the decomposition-tracking
identity, not an approximation), and the scatter \emph{distance} $t^\star$ is the result of this single
pass (\Cref{alg:argmin}). The scatter point's albedo is then a $\sigma_t$-weighted mixture over the
primitives that contain it, and the active set for the next bounce is rebuilt by a second linear pass
over the same candidates---no new trace.

\paragraph{Why the minimum is exact.} The identity is a one-line consequence of independence. Each $t_k$
is drawn from primitive $k$'s own free-flight law, so $\Pr[t_k > t] = e^{-\tau_k(t)}$---its
transmittance. The per-primitive draws use independent uniforms $\xi_k$, hence
\[
  \Pr\!\big[\min_k t_k > t\big] = \prod_k \Pr[t_k > t] = \prod_k e^{-\tau_k(t)}
  = \exp\!\Big(-\!\sum_k \tau_k(t)\Big) = e^{-\tau(t)} = T(t),
\]
the transmittance of the \emph{combined} medium $\sigma_t=\sum_k\sigma_{t,k}$ (optical depth is additive
over overlapping primitives). So $t_{\text{scatter}}=\min_k t_k$ has exactly the combined free-flight
distribution with c.d.f.\ $1-T(t)$: the argmin is an exact sample from the mixture, not an
approximation. Unlike the delta/null-tracking that decomposition tracking normally requires, no majorant
and no null-scattering events appear here, because every per-primitive free flight is itself drawn in
closed form (\Cref{sec:analytic-od})---the analytic invertibility is what removes the stochastic
tracking entirely.

\begin{algorithm}[htp]
\caption{Argmin scatter sampling for one ray segment.}
\label{alg:argmin}
\begin{algorithmic}[1]
\Require ray $\bm{r}$; active set $A$ (primitives containing the origin); hit buffer $H$ of entries
$(t_{\text{entry}}, k)$ from one trace
\Ensure scatter distance $t^\star$, or \textsc{Escape}
\State $t^\star \gets +\infty$
\ForAll{$k \in A$} \Comment{origin inside: invert from $t_0 = 0$}
  \State $\tau_k \gets -\ln(1-\xi_k)$, \quad $\xi_k \sim \mathcal{U}[0,1)$
  \State $t_k \gets \textproc{inv\_cdf}(\bm{r}, \tau_k)$
  \If{$0 \le t_k \le t_{\text{exit}}(k)$ \textbf{ and } $t_k < t^\star$}
    \State $t^\star \gets t_k$
  \EndIf
\EndFor
\ForAll{$(t_{\text{entry}}, k) \in H$} \Comment{entered mid-segment: invert from $t_{\text{entry}}$}
  \State $\tau_k \gets -\ln(1-\xi_k)$, \quad $\xi_k \sim \mathcal{U}[0,1)$
  \State $t_k \gets \textproc{inv\_cdf\_segment}(\bm{r}, t_{\text{entry}}, \tau_k)$
  \If{$0 \le t_k \le t_{\text{exit}}(k)$ \textbf{ and } $t_k < t^\star$}
    \State $t^\star \gets t_k$
  \EndIf
\EndFor
\If{$t^\star = +\infty$} \State \Return \textsc{Escape} \EndIf
\State \Return $t^\star$
\end{algorithmic}
\end{algorithm}

\paragraph{Avoiding a rejection bias.} The two candidate categories are handled with slightly different
inverses. A primitive the ray is already inside is inverted from the segment start ($t_0 = 0$). A
primitive entered mid-segment must be inverted from its \emph{entry} distance, not from the ray origin;
using the full-Gaussian inverse and rejecting samples that land before the entry would bias the result.
The renderer therefore uses a segment-restricted inverse that solves $\tau_k(t_{\text{entry}}, t) =
\tau_k$ directly, shifting the error-function reference to the entry point. This keeps every candidate
unbiased by construction.

\paragraph{Novelty and prior art.} The components of this scheme are individually known: the
minimum-of-free-flights identity is decomposition tracking~\cite{Kutz2017}; the closed-form Gaussian
optical depth is from the reference~\cite{DSYG}; and the sort-free \emph{spirit} mirrors stochastic
splatting~\cite{StochasticSplats2025} on the rasterisation side. The contribution is their
\emph{synthesis}: applying analog decomposition tracking to ray-traced Gaussian kernel-mixture volumes,
so that the analytic per-primitive inverse makes each component's free flight a closed-form draw and
the argmin replaces the reference's marching and root-finding entirely. The approach was suggested by
Condor, a co-author of the reference~\cite{DSYG}---a direction its authors anticipated but had not
implemented---and is realised and validated here, to the author's knowledge for the first time for this
representation.

\paragraph{Complexity.} Per scattering bounce the work is $O(N + A)$: an $O(N)$ scan to maintain the
active set against the scene's $N$ primitives, plus an $O(A + H)$ pass over the $A$ active and $H$
newly entered primitives to take the argmin. This replaces the reference's per-bounce boundary
marching---an $O(A^2)$ running-minimum selection across segments---and its per-segment root-find with
closed-form work, and---because the argmin needs no ordering---removes ordered boundary processing
from the common (scattering) path altogether. The residual $O(N)$ active-set
scan is the dominant per-bounce cost and the subject of one of the optimisations in
\Cref{ch:optimization}.

\section{Direct lighting and the path-tracing loop}
\label{sec:direct-lighting}

At each scattering vertex the renderer estimates direct illumination from the environment map---an
image-based model of distant illumination surrounding the scene, sampled as an infinitely far
emitter---by next-event estimation under multiple importance sampling
(\Cref{sec:volumetric-light-transport}): two shadow connections are drawn per vertex---one sampling the
environment by luminance, one sampling the Henyey--Greenstein phase function---each weighted by the
balance heuristic, with transmittance from the analytic optical depth of \Cref{sec:analytic-od} along
each shadow ray. Indirect light is carried by the phase-sampled continuation ray, whose direct
environment contribution is suppressed so it is not double-counted against next-event estimation.
\Cref{ch:optimization} replaces this two-shadow-ray estimator with an optional
resampled-importance-sampling variant that traces a single shadow ray, keeping the MIS scaffold intact.

The primary (camera) ray's direct contribution is treated specially: rather than relying on the path to
escape the medium and hit the environment, the renderer adds the analytic camera-to-environment term
$T_{\text{cam}}\,L_{\text{env}}$ at bounce zero, where $T_{\text{cam}}$ is the closed-form transmittance
through the medium along the view ray. This Rao--Blackwellises~\cite{Rao1945,Blackwell1947} the otherwise high-variance escape
contribution---replacing a stochastically-sampled escape with its analytic expectation, which can only
lower variance---for the cost of a single transmittance ray. Paths are terminated by Russian roulette beyond a configurable depth,
with survival probability the throughput's largest channel clamped to \num{0.99}; surviving throughput
is reweighted to keep the estimator unbiased.

Samples are accumulated by Welford's single-pass online mean~\cite{Welford1962} (and variance, when adaptive sampling is
enabled), so that arbitrarily many samples per pixel can be folded in across launches without storing
per-sample data and without catastrophic cancellation. Sample batches are processed within a single
kernel launch, amortising launch overhead and keeping the accumulator in registers across the batch.

\section{Data structures and GPU configuration}
\label{sec:gpu-impl}

\paragraph{Acceleration structure.} The scene is built as a two-level OptiX structure. A single
geometry acceleration structure (GAS) holds one \emph{unit sphere}, built from OptiX's~\cite{Optix} built-in sphere
primitive (\texttt{OPTIX\_BUILD\_INPUT\_TYPE\_SPHERES}) so that ray--sphere intersection uses the
vendor-optimised built-in intersector rather than a custom program. (The built-in sphere is exact but,
unlike triangle intersection, does not execute on the dedicated ray-tracing cores;
\Cref{sec:icosphere} measures this choice against the reference's tessellated icospheres.) Each Gaussian primitive is then an \emph{instance} of that
GAS in an instance acceleration structure (IAS), carrying the affine transform that maps the unit
sphere to the primitive's centre, anisotropic scale, and orientation (from its rotation quaternion).
Thousands of distinct ellipsoids thus share a single sphere GAS, and the per-primitive geometry lives
entirely in the instance transforms. Both structures are built with
\texttt{OPTIX\_BUILD\_FLAG\_PREFER\_FAST\_TRACE} (favouring traversal speed over build time, the right
trade for a renderer that builds once and traces for many samples) and
\texttt{OPTIX\_BUILD\_FLAG\_ALLOW\_COMPACTION} (standard practice---it shrinks the built
structure at no traversal cost).

\paragraph{Per-ray state.} Two per-ray containers dominate the kernel's footprint. The hit buffer
(\Cref{sec:collection}) is a fixed-capacity \texttt{HitBufferSoA}. The active set is a small membership
structure whose representation is chosen at compile time by scene size: for up to \num{256} primitives a
\emph{bit vector} gives $O(1)$ insert, erase, and test in $N/8$ bytes; beyond that a compact unsorted
array gives $O(k)$ operations in space proportional to the maximum overlap rather
than the scene size. The relevant capacities---the active-set bound and the hit-buffer length---are
compile-time constants, and want to be as small as is safe---though the two differ in how much
tightness matters. The hit buffer (\SI{6}{\byte} per entry) is the binding one: a universal
``safe'' build ($512/512$, the cap a user without tooling would pick) measured $+13\,\%$ frame time
on the cloud, $+7\,\%$ on the explosion, and ${\sim}+3\,\%$ on the tornado and bunny against the
per-asset-tuned builds. It costs memory too: the per-ray buffers live in thread-local memory, which
the driver reserves for the device's maximum resident thread count, so the compiled cap sets a
scene-independent floor on device memory. The safe build reserves a flat $1200\,$MiB on every asset,
whereas the per-asset-tuned builds use $578$--$900\,$MiB---a saving of $0.30$--$0.62\,$GiB
($25$--$52\,\%$). The effect is large enough to flip the cross-renderer memory comparison: tuned, the
renderer's peak device memory on the cloud ($578\,$MiB) sits \emph{below} the Mitsuba reference's
($838\,$MiB) on the same scene, while the untuned safe build ($1200\,$MiB) exceeds it. The active set
(\SI{2}{\byte} per entry) tolerates headroom: doubling its
capacity beyond the cloud's worst case measured as timing-neutral in an interleaved A/B (differences
under the run-to-run jitter), with renders numerically equivalent. Tightness therefore matters mainly
for the hit-buffer capacity; the active-set capacity needs only adequacy.

Sizing is by \emph{measurement}, not guesswork: a \texttt{--measure-caps} render mode counts, with
cap-independent counters (the collection shader counts \emph{dropped} hits too, and point-overlap is
an exhaustive containment scan rather than the clipped active set), the true per-ray hit demand and
per-vertex overlap of the actual workload; a one-command calibration wrapper measures the asset's
binding stress on two seeds, writes the margined constants, rebuilds, and verifies zero overflow on a
deliberately \emph{unmeasured} seed. For the primary cloud scene the measured worst case---\num{45}
simultaneously overlapping primitives, \num{85} entries on the worst ray---sits comfortably inside
the calibrated capacities, and the runtime counter below records zero overflows. A complementary
offline estimator Monte~Carlo-samples points and lines through the scene's bounding box against each
primitive's exact $3\sigma$ ellipsoid, giving a camera-independent \emph{ceiling} before any build
(\Cref{tab:overlap}); measurement on the \num{25600}-Gaussian bunny shows why the in-render counters,
not the estimator, are the sizing authority---the whole-bbox bound over-sized the bunny's active set
four-fold (\num{320} suggested vs.\ \num{71} measured), while its sampled lines \emph{under}-shot the
worst observed ray by ${\sim}20\,\%$ (\num{387} vs.\ \num{464}), surviving only on its safety margin.
A deliberately degenerate collinear stress test
exercises the overflow path (\Cref{ch:validation}). Because no static cap can be guaranteed sufficient
on every scene, a device-side overflow counter flags at runtime any ray that exceeds a capacity, so
excess overlap is \emph{detected} rather than silently corrupting the image.

\paragraph{Megakernel rationale.} The entire bounce loop executes inside the ray-generation program: a
single \emph{megakernel}. The standard alternative is \emph{wavefront} path tracing~\cite{Laine2013},
in which each stage of the path---ray traversal, scattering, shading---is a separate kernel launch and
per-ray state is carried between them through global memory, with stream compaction between stages to
keep GPU warps coherent. Keeping the whole loop in one kernel is a deliberate fit to the workload. The per-bounce arithmetic is light (a few
error functions and a phase evaluation), but the per-ray \emph{state} that must persist across
bounces---mainly the active set---is comparatively large. A wavefront would have to stream that state
to and from global memory every bounce; the megakernel keeps it in registers and shared/local memory,
paying zero round-trips. \Cref{ch:optimization} reports the experiment that confirms this: a wavefront
refactor, though correct, was dramatically slower, because moving the persistent per-ray state to
global memory is fatal for an algorithm whose per-bounce compute is otherwise so cheap.

\paragraph{Implementation.} Beyond OptiX and a few small header-only utilities (PLY and EXR I/O,
logging, and command-line parsing), the renderer has no external dependencies---in particular no
rendering framework---which keeps the codebase compact and straightforward to extend. Optional
features are toggleable without touching the core renderer: the OptiX denoiser (\texttt{--denoise}) and
volumetric product-RIS (\texttt{--ris}, with candidate count \texttt{--ris-candidates}) are
\emph{runtime} flags, while adaptive sampling and a fast-math $\operatorname{erf}$ are compile-time
switches. The rendering parameters themselves are likewise exposed on the command line---samples per
pixel (\texttt{--spp}), RNG seed (\texttt{--seed}), the density scale (\texttt{--sigma-multiplier}),
phase anisotropy (\texttt{--hg-g}), maximum depth and Russian-roulette schedule
(\texttt{--max-depth}, \texttt{--rr-depth}, \texttt{--rr-max-survival}), an optional firefly clamp and
pixel filter (\texttt{--firefly-clamp}, \texttt{--filter-stddev}), and the cap-measurement mode
(\texttt{--measure-caps})---so an experiment is specified entirely by its invocation.
